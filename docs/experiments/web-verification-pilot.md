# 网页交付前验证：首次小实验

2026-09-11，默认模型 DeepSeek / deepseek-flash，Pi 0.85.1。

## 改动

默认开发约定要求实现/修复后实际运行，并在最后一次修改后重跑。按需提供 verify_web_page，复用 Playwright 或 playwright-core，Windows 可使用已安装的 Edge。普通 CLI 不携带浏览器依赖、不在启动时加载。此约定不依赖用户偏好是否成功保存。

工具在独立浏览器上下文中分别检查 1280/390px，执行声明的操作和结果断言，收集 console/pageerror、横向溢出、截图与 JSON 报告。文件 URL 记录主 HTML 的 SHA-256；不宣称绑定其所有外部资源或 HTTP 服务版本。每次用户输入最多三次该工具调用，每次浏览器执行阶段最多 60 秒，支持取消。它不是文件/网络沙箱，页面操作仍需符合用户授权。

## 自动回归

同一计数器连续三种实现：动态拼接 ID 导致 null 运行错误；没有异常但显示错误数值；正确实现。保持同一组断言，实际 Edge 的两种视口分别判为 failed、failed、passed。另外检查缺少结果断言、非本地 URL 和已取消请求的拒绝行为。原生 SDK 集成确认工具注册和规则注入，问候仍不触发工作。

## 真实模型试用

隔离目录只有一个故障 HTML。给模型的提示为：

> 把当前 index.html 的计数器修好。初始显示0，点击加一累加，复位回到0，复位后还能继续加一。保持这个简单页面，不要增加功能。

没有额外要求它运行浏览器。观测轨迹：bash 列目录 → read 页面 → verify_web_page（两个视口都捕获 null 错误与结果断言失败）→ edit → verify_web_page（同样断言通过）→ read 桌面截图。

宿主随后独立执行初始值、连续加两次、复位、复位后再加一次的断言，两种视口通过。原始轨迹、报告和截图保存在本地忽略目录 `.piloop-web-pilot/`，不随安装包发布。模型查看过桌面截图；没有证据证明它检查了窄屏截图的视觉质量。

## 结论与限制

交付检查：22 项测试通过，类型检查/CLI 构建及旧网页构建通过。实际 tarball 在干净 prefix 安装、帮助、版本和无凭据启动通过（12 个文件，17,607 字节，不含浏览器生产依赖）。本机已安装轻量 playwright-core 1.63.0 到 ~/.piloop/browser 并同步三个运行模块；此次为本地修正，未发布新的 GitHub Release。

这是一次成功的真实工具闭环，不是 Pi/PiLoop 对照实验，也不是首次交付成功率估计。工具的通过结果只覆盖指定断言；模型仍可能不调用工具、选择错误预期、漏测状态或过早交付。三次预算约束本工具，不是对所有 bash/第三方工具的全局调度限制。下一步应在多个未见任务上固定模型、起点与预算做对照，而不是继续增加角色或循环机制。

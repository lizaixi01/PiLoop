# 排版任务范围回归

日期：2026-09-11。

之前的真实轨迹多次出现：用户要求改善阅读体验，模型把纯文字导航改成 `/posts`、`/articles`、`/about` 等链接，却没有对应页面。这是具体的功能退化，不能用“更主动”解释。

本轮仅在 PILOOP_CONTEXT 增加一段范围规则：呈现改进保持内容和功能，不猜测链接目的地；明确要求导航时检查或创建目的地；结束前检查实际差异及新链接。没有拦截写入，没有新增产品工具、UI、后台进程。规则仍依赖模型遵守，不是强制验证器。

运行：`npm run build`，然后 `node scripts/proactive-pilot.mjs --scope`。

两组均包含上一轮主动交互规则；唯一提示差异是本轮范围规则。沿用相同模型、low、read/edit/write/ls/find/grep、独立单文件博客样本、交替顺序、两次重复、90 秒及工具调用上限。

三个场景：模糊改善阅读体验；明确只改排版且保持内容导航；明确创建 about.html 并把关于链接到该页。后者作为正向检查，防止规则让模型拒绝合法的新页面任务。

判读最终文件、完整回复和工具轨迹：前两种场景不能捏造不存在的目的地；明确排版任务应有实际呈现修改并保留原文和导航；创建页面任务应有要求的正文和正确链接，首页其他内容保持不变。不能把完全不修改简单算作成功。未运行浏览器，不能声明视觉质量或 HTTP 行为已验收。

小样本用于判断是否值得继续，不代表统计显著效果；缺少失败的对照样本时不宣称解决问题。

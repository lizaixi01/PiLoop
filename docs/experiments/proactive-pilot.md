# 主动交互最小实验

日期：2026-09-11。

假设：只增加“先按需调查；必要时提供具体选项；选择后继续执行”的规则，可以减少用户代找信息和重复确认，同时不增加擅自修改。

产品修改仅为 `server/tui.ts` 的 `PILOOP_CONTEXT` 增加一段行为规则。没有新增工具、命令、UI、后台任务或记忆机制；权限边界保持不变。

## 方法

手动执行 `node scripts/proactive-pilot.mjs`，会调用现有配置的真实模型并产生费用或使用额度。先执行 `npm run build`。原始结果保存在被 Git 忽略的 `.piloop-experiments/`，包含合成任务、模型回复、工具轨迹、修改结果、用量与耗时，不复制凭据。

- before：修改前的 PiLoop 提示；after：加入新规则的提示。此处不是原版 Pi 与 PiLoop 的产品整体对比。
- 固定模型、low 推理档位、样本内容、工具和任务；每个会话独立，无个人记忆、Skills 或额外扩展。
- 首轮仅开放 read/edit/write；后续补齐查找能力的轮次统一开放 read/edit/write/ls/find/grep。仍不能据此断言完整 CLI、shell 或浏览器工作流的效果。
- 每个场景每组两次，第二次颠倒组别顺序。采样由供应商默认设置决定，没有固定随机种子；不声称温度受控。
- 四个场景：问候、明确改正文宽度、模糊改善阅读体验、预先明确 A/B 含义后回复 A。最后一个场景只测选择后的连续执行，不测自然选项生成质量。
- 每个会话 90 秒超时，超过 12 次工具调用请求终止。样本目录是隔离副本，不是 OS 沙箱。

## 人工判读标准

查看完整轨迹和文件结果，不按“出现 A/B/C”计分：

1. 问候不调用工具、不改文件。
2. 明确任务完成 720px 修改，不改无关内容，不增加确认轮次。
3. 模糊任务先查看相关内容；允许合理的小幅直接改进，也允许在存在实质分歧时给出具体选项。不能把所有提问或所有直接执行一概判错。
4. 选择 A 后执行已约定的宽度修改，不重新索要需求、不再次确认。

记录实际多余提问次数、重复解释请求、错误修改、工具调用、模型 usage 和墙钟耗时。没有真实用户参与，不能宣称测到了实际用户解释时间。超时、供应商错误单列，不算行为失败；未知归因保留未知。

只有两次重复的定性试跑。两组都成功表示本样本未显示额外收益；after 更啰嗦、增加无关修改或反复询问则反对当前假设。不得将 SDK 测试桩通过当作行为收益。

## 本次执行结果

- 产品修改后的 16 项现有测试全部通过；TypeScript 检查和生产构建通过，已更新实际全局入口依赖的编译产物。
- 实际使用 openai-codex/gpt-5.5，low。首个 before/greeting 请求约 67.5 秒后返回 `stopReason=error`、`fetch failed`，无工具调用。SDK 用量为 0；不能据此核实供应商账单。
- 实验遇到供应商错误后停止，未继续调用其余场景。原始记录：`.piloop-experiments/proactive-1789096159995/0-greeting-before/result.json`。
- 没有获得可比较的模型回答；行为效果未知。不能归因为模型能力或新规则失败，也没有证据支持规则改善了主动性。连接恢复后可用同一脚本重跑。

## DeepSeek-Flash 重跑

同日按用户要求重跑，实际读取默认模型 `deepseek/deepseek-flash`，请求 thinking=low。原始记录目录：`.piloop-experiments/proactive-1789096538411/`。16 个会话全部完成，无超时或供应商错误。

| 观察 | before（8 会话） | after（8 会话） |
| --- | --- | --- |
| 问候不调用工具、不改文件 | 2/2 | 2/2 |
| 明确宽度修改，最终文件仅替换 1100px 为 720px | 2/2 | 2/2 |
| 选择 A 后继续完成，仅修改宽度 | 2/2 | 2/2 |
| 模糊任务 | 2 次先读取后修改，再追问扩展方向 | 1 次读取后修改，1 次读取后提供 A/B/C/D 并等待 |
| 模糊任务引入无对应样本页面的导航路径 | 1/2 | 1/2 |
| 工具调用总数 | 21 | 25 |
| 累计墙钟时间 | 48.22 秒 | 49.38 秒 |
| SDK totalTokens（含缓存读取） | 64,962 | 74,284 |
| input / output / cacheRead | 13,503 / 6,147 / 45,312 | 12,332 / 6,272 / 55,680 |

人工检查了各组回复与最终 HTML。明确任务与选择 A 后的最终文件均精确符合要求；并不代表页面经过浏览器验收。模糊任务中两组各一次擅自给导航添加 `/posts` 和 `/about` 一类路径，样本无对应页面；未启动服务器验证 HTTP 状态码。after 第一次主动承认路径不存在，仍是修改后才暴露问题。另一次 after 虽然先给选项，但包括扩建多文章骨架、重写内容等扩展方向，又追问是否存在其他文件，不能简单记作高质量决策成功。

归因限制：工具集没有 ls/find/bash，模型只能尝试 read 目录或猜 README.md/package.json 等名称。此设计会干扰“能查明的不要问用户”的观察；相关追问不能直接归因于模型不主动或新提示无效。两组均存在样式解释不准确的文字，例如把固定宽度内增大字号解释为每行字数更多；这些属于待核验的模型输出，不能当作验证证据。

结论：本样本未证明新增规则带来收益。工具调用与总 token 更高，但小样本、缓存命中和生成长度不同，不支持推断稳定成本变化。下一轮优先让两组获得相同的目录查找能力，并增加真正需要用户判断的分歧样本；不据此扩建状态机或选项 UI。本次只记录结果，没有继续修改运行规则。

## 补齐查找工具

两组共同添加 Pi 原生 ls（列目录）、find（按名称查找文件）、grep（查找文件内容），共享同一工具数组。每个会话启动后核对实际启用的工具完全一致，结果记录 activeTools；manifest.json 保存模型、工具、两组提示、任务与初始样本。产品默认 CLI 不变，本次修改只作用于实验脚本。

本轮维持 DeepSeek-Flash、low、原有四种任务及两次重复，不同时改动任务样本，避免混入另一个变量。

结果目录：`.piloop-experiments/proactive-1789096865327/`。脚本语法检查通过；16 个真实会话完成，无超时或供应商错误，所有会话的实际工具集一致。

| 观察 | before | after |
| --- | --- | --- |
| 问候不调用工具 | 2/2 | 2/2 |
| 明确宽度修改，最终文件仅替换宽度 | 2/2 | 2/2 |
| A 选择后直接完成宽度修改 | 2/2 | 2/2 |
| 模糊任务 | 两次读取后询问方向 | 一次直接修改，一次询问方向 |
| 工具调用 | 20 | 22 |
| 累计墙钟时间 | 36.94 秒 | 42.59 秒 |
| SDK totalTokens，包含缓存读取 | 70,247 | 79,915 |

两组实际使用了 ls，模糊任务中也使用了 find。grep 已启用，但简单单文件样本不要求必须使用所有工具。模型能确认目录和空 agent 目录，没有继续靠猜 README/package.json 来定位博客。agent 目录是试跑配置目录，仍引入了额外探索开销，后续实验可单独处理这一环境噪声。

补齐查找后仍未显示新提示的稳定收益。after 直接修改的那次继续添加了没有对应样本页面的 `/articles`、`/about` 链接；另一次提出方向选择但仍建议顺带加入深色模式。before 也能主动调查并给出选项，不能将此行为归为 PiLoop 新规则的独有能力。没有浏览器验证，样本很小，不作统计显著性或整体模型能力判断。本轮没有继续修改产品提示或 CLI。

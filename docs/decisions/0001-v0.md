# 0001 — PiLoop 原生 Pi 执行路径

状态：已修正。日期：2026-09-11。

此前实现将全部输入截获后交给静态网页 Runner，导致问候也创建任务，并使原生 TUI 沦为另一套执行器的外壳。该路径已从默认 CLI 移除。

现在普通输入直接进入 Pi 会话，恢复默认工具、项目上下文加载、输入编辑器和底部状态栏。没有 input/user_bash 拦截、没有自定义 header/footer，也不关闭默认工具。SessionManager 与运行服务使用同一个用户工作目录。启动不再创建 Express 服务、不选择旧网页项目。

PiLoop 只注入 /api 快捷配置和可选项目约束扩展。用户显式保存到 .pi/piloop-memory.json 的范围约束在 before_agent_start 中附加有限上下文，不驱动工具执行。当前是模型解释范围的简单机制，不能宣称已经实现可靠自动召回。

本机原有模型凭据沿用 .piloop/agent。默认 CLI 的代码修改现在直接作用于真实工作目录，与 Pi 一致；旧网页原型仍独立保留副本流程。原型反馈没有自动迁移，避免旧示例约束影响真实项目。

全局命令依赖编译后的 lib，必须在真实安装环境完成构建并验证，不能只验证开发环境的源码或隔离编译产物。

模型上下文追加简短的 PiLoop 能力说明，明确原生 Pi 与扩展的归属、显式约束的范围解释限制和未实现功能。该说明不触发工作，也不作为产品差异已经成立的证据。协议测试核实说明进入真实 SDK 请求。

主动记忆采用一个 remember_preference 工具，复用当前模型判断，不引入第二模型、后台抽取或新 UI。input 钩子只记录原始输入后 continue，不接管 Pi 对话。保存须有当前用户逐字引用与持续意图线索，敏感行为需确认。判断规则保守但不完备；不能宣称所有纠正都会被可靠提炼。

一般交流偏好存 agent/preferences.json，跨项目恢复；项目规则仍在项目 .pi/piloop-memory.json。仅语言、回复长度和解释风格允许自动使用 user 层。两层共用 /memory 和 /forget、同一注入预算；具体项目要求优先于一般偏好。未迁移任何旧项目规则到全局。

主动交互第一轮实验只增加一段系统上下文：先按需进行只读调查，明确任务直接完成，实质意图分歧才给选项，选择后继续执行。保留正常聊天和权限边界，不强制三选一，不新增 UI 或后台执行器。行为收益尚须真实轨迹验证，实验协议见 ../experiments/proactive-pilot.md。

DeepSeek-Flash 的 16 会话初步对照未显示额外收益：明确任务和 A 选择后的执行两组都成功；模糊任务表现不稳定，两组各有一次添加无对应页面的链接。实验缺少目录查找工具，限制了对主动获取上下文的判断。暂不扩大机制；后续实验先修正工具条件与分歧样本。详见实验记录。

后续补齐实验查找工具后仍未证明新增主动规则的稳定收益。针对捏造链接加入最小范围约定：呈现改进不顺带新增路由/内容，明确导航请求则检查或创建目的地。12 会话范围回归中，两组都完成明确排版与新页面任务，模糊任务两组均停在澄清阶段，故没有额外收益结论。产品保留此行为约定但不声称强制执行；后续需验证完整决策与执行闭环，见 ../experiments/scope-pilot.md。
